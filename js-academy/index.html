How every lesson works

Each lesson is a loop of four moves. Skipping the last two is how people "know" concepts and still fail interviews.

The method 1 — Read. A short prose explanation that builds the idea from what you already know — no jargon walls.
2 — Watch. An animated model of the concept. Replay it until the movement feels predictable.
3 — Practice. Answer questions before revealing. Wrong answers are the point: each one comes with the reason.
4 — Prove. Say the interview answer out loud, recorded, no notes.
5 — Build. Close the page and write the code the lesson names — from memory, even if imperfect. This stage is the actual learning; the first four just aim it.

The ratio that makes it work: one-third reading, two-thirds writing code. If you find yourself re-reading lessons instead of building — close the tab and open the editor.

Where am I?

Honest self-placement Level 2 is the gate. If you can answer every Core lesson's questions without notes, you will interview well — that's the level interviewers actually probe, because it separates "wrote code for six years" from "understands what the code does."

Level 3 changes how you sound — memory, modules, and rate-limiting questions are where senior candidates get identified.

Level 4 is assumed, not asked — it's the working-engineer plumbing. Weakness here rarely fails an interview, but it slows down every workday.
