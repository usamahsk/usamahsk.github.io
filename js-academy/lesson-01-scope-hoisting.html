Scope & Hoisting

Where variables live — and the two-phase engine that runs your code before it runs.

1 · Readthe concept
2 · Watchthe animation
3 · Practiceget checked
4 · Provesay it out loud
In plain words Scope answers one question: where can my variable be seen from? The answer depends on where you wrote the code — not where you run it. Hoisting means: before your code runs line by line, JavaScript takes one quick look through it and writes down every name it finds. That quick look is why some variables seem to "exist early".

1.Read the concept

Scope: three neighborhoods a variable can live in

Every variable you declare exists inside exactly one scope. JavaScript has three kinds, nested like streets inside districts inside a city:

const city = "Berlin";              // GLOBAL — visible everywhere

function district() {
  const street = "Hauptstraße";     // FUNCTION — visible in this function
                                    // and everything nested inside it

  if (true) {
    const house = "Nr. 7";          // BLOCK — visible only inside these { }
    console.log(city, street, house);   // all three: readable here
  }

  console.log(house);               // ReferenceError — the block ended
}

Two details matter for interviews. First, var ignores block scopes — a var declared inside an if leaks into the whole function, which is exactly why let and const replaced it. Second, a function can read variables from all the scopes that surround it — but each scope can also declare its own version, which shadows the outer one:

const name = "global Sam";

function greet() {
  const name = "local Sam";   // shadows the outer one inside this function
  console.log(name);          // "local Sam" — nearest declaration wins
}

greet();
console.log(name);            // "global Sam" — untouched

Lexical scope: the map is drawn where the code is written

This is the sentence that unlocks half of JavaScript: a function's scope is decided at the place it is written, not the place it is called from. The word for this is lexical — "relating to the text."

const city = "Paris";

function where() {
  console.log(city);          // written at global level → sees global city
}

function run() {
  const city = "Berlin";      // a DIFFERENT city, local to run()
  where();                    // calls where() — but where was NOT born here
}

run();                        // prints "Paris", NOT "Berlin"

Read that output again. where() was invoked from inside run(), but it doesn't see run()'s variables — it was written at the global level, so its scope chain leads to the global scope. If this felt surprising, that's good: this exact surprise is a favorite interview question, and it's also the seed of closures (next lesson).

Hoisting: your code runs in two passes

Now the stranger half. Before executing your file line by line, the engine makes a creation pass: it walks through each scope and registers every name it finds. Only then does the execution pass begin. What gets registered depends on what kind of declaration it is:

  • var x — registered immediately with the value undefined. Reading it early is legal; you just get undefined.
  • function hi() {} — the entire function is stored during the creation pass. Calling it from line 1 works perfectly.
  • let y / const z — registered, but locked ("uninitialized") until the declaration line actually runs. Reading them early throws a ReferenceError. The locked zone has a name: the temporal dead zone.
Why "hoisting" is a misleading name Nothing physically moves to the top of the file. The engine doesn't rearrange your code — it registers names in advance. "Hoisting" is just the nickname the community gave to this early registration. Say that in an interview and you sound like someone who understands the machine, not someone who memorized a word. 
console.log(x);      // undefined  — var was registered with undefined
var x = 5;

console.log(y);      // ReferenceError — let exists but is LOCKED (TDZ)
let y = 10;

hi();                // "hi" — the whole function was registered in pass 1
function hi() { console.log("hi"); }

bye();               // TypeError — only the VARIABLE was registered,
var bye = function () { console.log("bye"); };  // not the function

The last line is the subtle one: a function expression is a function stored in a variable. The variable follows var/let rules; the function value only exists after the assignment runs. Declaration vs expression — same looks, different hoisting behavior. Interviewers ask exactly this.

Exceptions & traps — the complete list

  • TDZ vs undefined: touching a let/const before its line throws ReferenceError; touching an early var gives undefined. Different failures, same root: early registration.
  • var leaks blocks: for (var i…) leaves i === 3 alive after the loop; let doesn't — the bug let was invented to fix.
  • Declaration vs expression: calling an early declaration works; calling an early expression gives TypeError: … is not a function (the variable exists, the function value doesn't yet).
  • Lexical, not dynamic: a function sees the scopes where it was written — calling it from somewhere else changes nothing.
  • Shadowing: an inner let name hides the outer one only inside its block — the outer value is untouched.
  • Re-declaration: let x…; let x… in the same scope is a SyntaxError — var's looseness is gone.
  • Undeclared assignment (sloppy mode): x = 5 without declaration silently creates a global — a bug factory. Always declare.
  • catch (err) is its own block scope — the error variable exists only inside the catch.

4.Prove it

Your interview answer — rehearse this out loud, recorded, no notes "JavaScript runs code in two phases. In the creation phase, the engine registers every name in each scope: var becomes undefined, function declarations are stored completely, and let/const are registered but locked until their line runs — that locked period is the temporal dead zone. Then the execution phase runs line by line. Scope itself is lexical: a function resolves variables by walking up the scopes where it was written, not where it's called. That walk is the scope chain, and it's also the foundation of closures."

Target: 30–40 seconds, no hesitations. Record on your phone, listen back, re-record until smooth.
