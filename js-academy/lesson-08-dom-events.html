DOM & Events

Where your JavaScript actually meets the page — and how a click travels upward.

1 · Readthe concept
2 · Watchthe animation
3 · Practiceget checked
4 · Provesay it out loud
In plain words The DOM is the page as a family tree of objects that your JavaScript can read and change — change the tree, and the screen changes. An event is the browser saying "something just happened!" And here's the interesting part: when you click something small, the news travels up through its parents too — like a message passing from teacher to principal. That traveling-up is called bubbling, and it powers a clever trick called delegation.

1.Read the concept

Select, change, create

// selecting — querySelector takes ANY CSS selector
const list  = document.querySelector("#todos");
const items = document.querySelectorAll(".item");   // static NodeList

// changing — safely
list.textContent = "Hello";          // plain text — never parses HTML

// creating & inserting
const li = document.createElement("li");
li.textContent = "Buy milk";
li.classList.add("item");
list.appendChild(li);
textContent vs innerHTML — the security interview question innerHTML parses the string as HTML — powerful, and dangerous with user input: el.innerHTML = userInput lets a user inject <img src=x onerror=…> and run their script in your page — that attack is XSS. Rule: user data goes through textContent, never raw into innerHTML.

Events — and the one concept that gets tested

const btn = document.querySelector("button");
btn.addEventListener("click", function (e) {
  console.log("clicked", e.target);    // e = the event object
});

When a click happens on an <li> inside a <ul> inside a <div>, the browser doesn't just notify the li. The event bubbles: it fires on the target first, then travels up through every ancestor, giving each one's listeners a chance to run. (Before bubbling, there's also a downward "capturing" phase — which is what the optional third argument of addEventListener(type, fn, useCapturing) taps into.)

Bubbling enables the professional pattern — event delegation: instead of attaching a listener to each of 200 list items (and re-attaching for every new one), attach one listener to the parent and check who was actually clicked via e.target:

list.addEventListener("click", (e) => {
  if (e.target.matches("li")) {
    e.target.remove();          // works for items that don't exist YET, too
  }
});

Two related tools: e.target is where the event originated; e.currentTarget is the element the listener is attached to (inside a handler, they're only equal when the listener sits on the target itself). And e.stopPropagation() halts the upward journey; e.preventDefault() cancels the browser's default action (a form submit, a link navigation) — different jobs, often confused.

Exceptions & traps — the complete list

  • innerHTML with user input = XSS — injected <img onerror=…> runs script in your page with the user's session. User data goes through textContent.
  • e.target vs e.currentTarget — target never changes during the bubble; currentTarget is whoever's listener is running. Equal only on the target itself.
  • Delegation handles future elements for free — listeners on items added later simply don't exist; the parent's listener catches them anyway.
  • preventDefault ≠ stopPropagation — one cancels the browser's default action, the other halts the upward journey. Independent tools.
  • The third argument is the capturing phase — events travel DOWN (capture) before bubbling up; { capture: true } listens on the way down.
  • querySelectorAll returns a STATIC NodeList — it won't see elements added after selection; re-query or use live collections knowingly.
  • Removing the listener matters: anonymous functions can't be removed — keep a reference if you plan to removeEventListener.
  • this in a regular listener is the element — in an arrow listener it's the outer scope (the this lesson, again).

4.Prove it

Your interview answer — rehearse out loud, recorded, no notes "The DOM is the browser's live tree of the page, and I select and change it with querySelector and the node APIs — using textContent for anything touched by users, because innerHTML parses HTML and is the XSS vector. For events, a listener fires on the target and then the event bubbles up through every ancestor, which is why event delegation works: one listener on the parent, checking e.target, handles current and future children alike. e.target is where the event originated, e.currentTarget is what the listener is attached to, stopPropagation halts the bubble, and preventDefault cancels the browser's default action — two different tools."

Selection → the security line → bubbling → delegation → the two e-properties. That's a complete mid-level DOM answer.
