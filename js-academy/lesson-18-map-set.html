Map, Set & WeakMap

When plain objects and arrays stop being the right tool.

1 · Readthe concept
2 · Watchthe live demo
3 · Practiceget checked
4 · Provesay it out loud
In plain words A plain object is a labeled box whose labels can only be text. A Map is a labeled box whose labels can be anything — objects, functions, even other Maps. A Set is a bag that refuses duplicates — a value is either in it or not, never twice. WeakMap is a Map whose labels don't glue their values into memory.

1.Read the concept

Map — when keys need to be more than strings

const userA = { id: 1 };
const scores = new Map();

scores.set(userA, 95);        // an OBJECT as the key!
scores.set("alice", 88);      // strings work too
scores.set(42, "answer");

scores.get(userA);            // 95 — identity lookup, not string matching
scores.has("alice");          // true
scores.size;                  // 3 — a real property, not a calculated length
scores.delete("alice");       // true — removed

for (const [key, value] of scores) { … }   // directly iterable — objects aren't

Why not just use an object? Because object keys are coerced to strings — obj[userA] turns the object into the string "[object Object]", and suddenly every object key is the same key. A Map keeps keys by identity. Also: objects come with prototype baggage (obj.toString exists even if you never put it there); Maps have exactly what you put in them.

Set — the duplicate-killer

const visits = new Set();
visits.add("sam");
visits.add("sam");            // ignored — already in
visits.size;                  // 1

// THE idiom everyone uses: remove duplicates from an array
const unique = [...new Set([1, 2, 2, 3, 3, 3])];   // [1, 2, 3]

unique.indexOf("x") !== -1;   // fine…
visits.has("x");              // …but Set.has is O(1) — instant, even for millions

The second Set superpower: has() is instant no matter how big the Set gets — while arr.includes() walks the whole array. When "have I seen this before?" is your question, a Set is the answer.

WeakMap — memory-friendly metadata

const metadata = new WeakMap();
metadata.set(someDomNode, { clicks: 3 });   // keyed by the OBJECT itself

// when someDomNode is removed from the page and unreferenced elsewhere,
// the garbage collector can free it AND its metadata automatically.

A WeakMap holds its keys weakly — it won't keep an object alive just by referencing it. Attach private data to an object without preventing its cleanup. (Weak keys only — no size, no iteration; that's the trade.)

Exceptions & traps — the complete list

  • Object keys are strings; Map keys are anything — obj[{id:1}] becomes key "[object Object]". Objects as Map keys work by identity: two look-alike objects are different keys.
  • map.get(missing) returns undefined — no error. Same as object property access; check with .has() when undefined is a legitimate value.
  • Setting the same key twice overwrites — Maps hold one value per key; there's no "append".
  • NaN works as a Map key (SameValueZero comparison) — map.set(NaN, 1); map.get(NaN) → 1, even though NaN === NaN is false.
  • Objects come with prototype pollution: obj["constructor"] exists without you adding it — Maps don't have this problem.
  • Set.add is a no-op for duplicates — same value twice, size stays. But {a:1} and {a:1} are different objects — both enter the Set (identity again).
  • WeakMap keys must be objects — primitives throw. And no size, no iteration: you can't inspect a WeakMap, by design.
  • JSON can't serialize Maps/Sets directly — JSON.stringify(new Map()) gives {}. Convert first: Object.fromEntries(map) or [...set].
  • Choosing: string keys + JSON → plain object. Arbitrary keys, frequent add/delete, order matters → Map. Uniqueness/fast membership → Set. Metadata that shouldn't block GC → WeakMap.

4.Prove it

Your interview answer — rehearse out loud, recorded, no notes "A Map is a key-value store where keys can be any type — objects work by identity, which plain objects can't do since they coerce keys to strings. It has a real size property, iterates directly, and carries no prototype baggage. A Set is a collection of unique values — add is a no-op for duplicates, and has() is O(1) lookups, which is why spread-plus-Set is the canonical dedupe idiom. A WeakMap keys only on objects and holds them weakly, so metadata dies with its object instead of leaking memory. Choosing: JSON-friendly string keys stay objects; arbitrary or object keys go to Map; uniqueness goes to Set; metadata goes to WeakMap. One caveat: JSON.stringify gives {} for a Map, so convert before serializing."

Map → Set → WeakMap → the choosing rule → the JSON caveat. That's a complete senior answer.
