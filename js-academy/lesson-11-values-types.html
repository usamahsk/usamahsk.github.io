Values & Types

Seven primitives, one object type — and the coercion traps hiding between them.

In plain words Every value in JavaScript is one of two kinds: a simple, single thing — text, a number, true or false (seven types, called "primitives") — or a container that holds other things (arrays, objects, functions — all called "objects"). Simple things compare by what's inside them; containers compare by whether they're the same container. Almost every confusing JavaScript moment comes from forgetting which kind you're holding.

1.Read the concept

Everything in your program is a value — "Sam", 42, true, [1,2], {name: "Sam"}. And JavaScript sorts every single one of them into two families. The first family is the simple, single things — a piece of text, a number, a true/false, and a few special ones like undefined and null. These are called primitives, and there are exactly seven. The second family is the containers — things that hold other things: arrays, objects, functions, dates. JavaScript calls all of them objects. Seven simple things, one kind of container — that's the entire type system. Write it down; it never gets bigger.

Sounds tidy. So why does this topic ruin interviews? Because the labels on these values lie to you, in three specific places.

Lie #1 — null claims to be an object

typeof null    // "object"  🐛

null is the official "deliberately empty" value. It's a primitive. And typeof calls it an object — because of a typing mistake made in 1995 that can never be fixed: correcting it would break millions of websites that depend on the bug. It's frozen into the language forever. The takeaway isn't "remember this fact" — it's that typeof is useful but not trustworthy, and the honest null test is x === null.

Lie #2 — arrays and NaN wear the wrong labels

typeof []      // "object"  — arrays ARE objects: objects with numbered keys
typeof NaN     // "number"  — "Not a Number" IS a number... a broken one

There is no "array" type in JavaScript — an array is an object whose keys happen to be 0, 1, 2. So typeof cannot answer "is this an array?" — Array.isArray(x) can. And NaN is what you get when math fails (0 / 0, parseInt("abc")) — a number the way a counterfeit bill is a dollar. Its cruelest trick: it isn't equal to anything, including itself:

NaN === NaN          // false!
Number.isNaN(NaN)    // true — the ONLY reliable test

Lie #3 — the falsy list is shorter than your intuition

Inside an if, every value silently converts to true or false. The false ones are only six:

false, 0, "", null, undefined, NaN

Everything else is truthy — including the values that look false: "0" is a non-empty string (truthy!), [] and {} are objects (always truthy, no matter how empty). This is why if (cart) can never detect an empty cart:

const cart = [];
if (cart) { }                  // ALWAYS true — even when empty!
if (cart.length === 0) { }     // ✅ the honest emptiness check

Comparing: === vs == — one decision to make today

1 === "1"     // false — strict: refuses to convert
1 == "1"      // true  — loose: converts types before comparing

null == undefined    // true  — a special rule
null === undefined   // false

== tries to be helpful by converting — which sounds convenient and causes disasters ([] == ![] is true; don't ask). === refuses to convert. The professional policy: always ===, with one accepted exception — x == null, meaning "is it null or undefined" in a single check. That decision removes an entire category of bugs from your code.

Exceptions & traps — the complete list

  • typeof null === "object" — historic bug. Test nulls with x === null.
  • typeof [] === "object" — test arrays with Array.isArray(x).
  • NaN !== NaN — test with Number.isNaN(x), never by comparison.
  • "0", " ", [], {} are all truthy — emptiness needs length, not if (x).
  • 0.1 + 0.2 !== 0.3 — floats can't store decimals exactly. Compare with a tolerance (Math.abs(a - b) < 0.001) or count money in integer cents.
  • 1 + "1" is "11" — + prefers joining when either side is a string; 1 - "1" is 0 because minus forces numbers.
  • Number("") is 0 — not NaN! An empty string converts to zero. Number(null) is also 0; only undefined and garbage text give NaN.
  • null vs undefined: undefined = "never assigned" (the system's empty), null = "deliberately empty" (yours). Both falsy; different intents.

4.Prove it

Your interview answer — rehearse out loud, recorded, no notes "There are seven primitives — string, number, boolean, undefined, null, symbol, bigint — and everything else is an object, including arrays and functions. typeof is useful but has three famous quirks: null reports as an object for historic reasons, NaN reports as a number, and arrays report as object, so I use Array.isArray for arrays and strict equality for null. For comparison I use === exclusively — == coerces types through rules nobody should trust — with the one idiomatic exception x == null meaning null or undefined. And for truthiness I know the falsy list: false, 0, empty string, null, undefined, NaN — everything else, including '0' and empty arrays, is truthy."

Primitives → typeof quirks → the == policy → the falsy list. Four beats, all memorizable.
