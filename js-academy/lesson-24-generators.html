Generators & Iterators

Functions that can pause mid-story and pick up exactly where they left off.

1 · Readthe concept
2 · Watchthe pause
3 · Practiceget checked
4 · Provesay it out loud
In plain words A normal function runs start-to-finish in one go. A generator (a function with an asterisk: function*) can pause at any line with yield, hand you one value, and wait. Call it again, it resumes from that exact line, variables intact. It's a function that tells its story one sentence at a time — only speaking when you ask for the next sentence.

1.Read the concept

Build it from what you know

You already use iterators every day without the word: for…of works on anything that can produce values one at a time — arrays, strings, Maps. An iterator is just the underlying contract: "an object with a next() that returns { value, done }." A generator is the easy way to create one — no manual bookkeeping, just yield where you want a pause:

function* counter() {
  yield 1;        // pause here — hand out 1
  yield 2;        // pause here — hand out 2
  yield 3;        // pause here — hand out 3
  return "done";  // finished
}

const gen = counter();   // NOTHING runs yet — you get a remote control
gen.next();   // { value: 1, done: false }
gen.next();   // { value: 2, done: false }
gen.next();   // { value: 3, done: false }
gen.next();   // { value: "done", done: true }  — story over

The astonishing part — stop and feel it: counter() executes zero lines when called. The function sits frozen at the top until the first .next(), runs to the first yield, and freezes there — with all its local variables preserved — until asked to continue. Nothing else in JavaScript pauses mid-function like this.

Why this is worth knowing — real uses

// 1. Infinite sequences — no array needed, values made on demand
function* ids() {
  let id = 1;
  while (true) yield id++;      // infinite... and completely safe
}
const gen = ids();
gen.next().value;   // 1
gen.next().value;   // 2   — only what you ask for ever gets computed

// 2. Lazy generation — don't build 1M numbers to use 3
function* firstN(n) {
  for (let i = 1; i <= n; i++) yield i * i;
}
[...firstN(3)];    // [1, 4, 9] — spread works: generators are iterable!

// 3. for…of works directly
for (const v of firstN(3)) console.log(v);   // 1, 4, 9

An infinite loop inside a generator is safe — it only advances when you call next(). That laziness is the point: produce values when asked, not all upfront. (Fibonacci without memory limits, paginated API pages, reading a huge file line by line — all the same idea.)

Exceptions & traps — the complete list

  • Calling a generator runs NOTHING — counter() returns the remote control; only .next() executes code. Beginners call the generator once and wonder why there's no output.
  • Generators are one-way trips — when done: true, further .next() calls return { value: undefined, done: true } forever; you can't rewind. Want a rerun? Create a new generator.
  • Each call to the generator creates an INDEPENDENT iterator — two counter() instances don't share progress (same separate-worlds logic as closures).
  • The final return lands in value with done: true — but for…of ignores that last value (it only yields while done is false). Subtle: don't rely on the return value inside for…of.
  • yield can also receive — const x = yield v: the value you pass into .next(x) becomes x. Two-way street; powerful, rarely needed at first.
  • yield* delegates to another generator — yield* inner() forwards all of its values, like splicing one story into another.
  • Arrow functions can't be generators — no function* arrow syntax exists.
  • Throwing inside a generator finishes it — an exception ends the iteration; the generator is done-done, like a rejected promise.

4.Prove it

Your interview answer — rehearse out loud, recorded, no notes "A generator is a function that can pause: declared with function*, it runs zero code when called — you get an iterator — and each next() call executes up to the next yield, returning { value, done } with all local state frozen between calls. It's the easy way to build iterators, which is why for…of and spread work on generators directly. The superpower is laziness: an infinite generator with while(true) is safe because values are produced only on demand — perfect for id sequences, pagination, and streaming large data without holding it all in memory. Caveats I know: generators can't rewind, each call creates an independent iterator, the final return's value is skipped by for…of, and arrow functions can't be generators."

Pause mechanics → iterator link → laziness superpower → the caveats. Complete.
