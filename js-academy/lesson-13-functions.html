Functions

Three ways to write one — and the differences interviews actually test.

In plain words A function is a machine: stuff goes in, an answer comes out, and you can use the machine again and again. The JavaScript twist: the machine itself is a thing you can hold — put it in a variable, hand it to another function, get one back from a function. Hold that thought; half of modern JavaScript is built on it.

1.Read the concept

A function is a machine: input goes in, work happens, an answer comes out — and you can use the machine again and again.

function add(a, b) {      // a, b = the inputs (parameters)
  return a + b;           // the answer handed back
}
add(2, 3);                // 5   (2, 3 = the actual values, arguments)

return does two jobs at once: hands the value back and stops the function instantly — code after return never runs. Keep the machine picture; the twist is coming.

The twist — a machine you can hold

[1, 2, 3].map(n => n * 2);      // you HAND a machine to another machine

function makeGreeter() {
  return () => "hi";            // a machine that BUILDS a machine
}

const ops = { add };            // a machine stored inside an object

In most beginner languages a function is rigid — a fixed thing in the file. In JavaScript, a function is a value, like the number 5 or the string "hi": store it, pass it, return it. When you write addEventListener("click", fn) you hand a machine to the browser. When you write [1,2,3].map(...) the array calls your machine on every element. This is the seed of half the Core lessons: callbacks power array methods and event listeners, and returning functions creates closures.

Now the definition makes sense Functions are first-class values — stored, passed, returned. Callbacks, array methods, closures, event handling: all this one property wearing different clothes.

The three syntaxes — and where they truly differ

// 1. Declaration — fully registered early; callable from line 1
function add(a, b) { return a + b; }

// 2. Expression — a function value stored in a variable
const subtract = function (a, b) { return a - b; };

// 3. Arrow — shortest; no own `this`; body rules below
const multiply = (a, b) => a * b;

Exceptions & traps — the complete list

  • Every function returns something — no return means undefined. Printing is not returning.
  • Arrow bodies: n => n * 2 returns automatically; n => { n * 2 } returns undefined — braces need an explicit return. The #1 arrow mistake.
  • Arrow returning an object literal needs parentheses: () => ({ ok: true }) — otherwise the {} is read as a function body.
  • Only declarations are callable before their line — expressions and arrows follow their variable's rules (TDZ). addEarly(1,2) before function addEarly(){} works; before const addEarly = … it crashes.
  • Arrows have no own this and no arguments object — they inherit both from the scope around them. That's why they're perfect callbacks — and wrong for object methods that need this.
  • Arrows can't be used with new — they have no internal constructor machinery.
  • Defaults trigger on undefined only — greet("Sam") uses the default, but greet("Sam", null) passes null straight through: defaults never replace null.
  • Missing arguments are undefined, extras are ignored — add(1) gives NaN (1 + undefined), silently. Validate inputs when it matters.
  • return exits immediately — anything after it in the function never runs.

4.Prove it

Your interview answer — rehearse out loud, recorded, no notes "There are three ways to define a function. Declarations are hoisted completely and callable before their line; expressions and arrows follow their variable's rules. Arrow functions differ in two real ways: no own this — they inherit it from the scope they're written in, which is why they're perfect for callbacks — and concise bodies return automatically, though braces need an explicit return. Functions are values in JavaScript: stored, passed as callbacks, and returned, which is the foundation of closures and every higher-order method like map."

Notice the payoff: this "beginner" answer quietly connects to hoisting, this, and closures.
