Array Methods

map, filter, reduce — the vocabulary every codebase speaks.

In plain words These methods all visit every element in the array and run your function on it. The only real difference between them is what comes back out: a transformed array (map), a shorter array (filter), one single value built up piece by piece (reduce), or nothing at all (forEach).

1.Read the concept

One callback shape, five different contracts

Every method here calls your function once per element with the same three arguments — (element, index, array) — and the differences are entirely in the return contract:

const nums = [1, 2, 3, 4];

nums.map(n => n * 2);            // [2, 4, 6, 8]    new array, SAME length
nums.filter(n => n > 2);         // [3, 4]          new array, kept-if-truthy
nums.forEach(n => console.log(n)); // undefined     just visits each element
nums.find(n => n > 2);           // 3               first match (or undefined)
nums.some(n => n > 3);           // true            at least one passes?
nums.every(n => n > 0);          // true            all pass?

The interview classic is map vs forEach. The answer in one line: map returns a new array of transformed values — use it when you're producing data; forEach returns undefined — use it when you're producing side effects (logging, DOM updates). Choosing map for side effects or forEach for transformation is a code-review smell either way.

reduce — the one that needs a real explanation

reduce boils an array down to a single value by carrying an accumulator through every element:

[1, 2, 3, 4].reduce((sum, n) => sum + n, 0);
// step 1: sum=0,  n=1 → 1
// step 2: sum=1,  n=2 → 3
// step 3: sum=3,  n=3 → 6
// step 4: sum=6,  n=4 → 10

Two things interviews probe. First, the initial value (the 0 above): without it, the accumulator starts as the first element — and an empty array without an initial value throws. Second, reduce isn't just for sums: summing a group-by, counting occurrences, flattening — any "many values in, one structure out" job.

The trap that catches almost everyone: sort

[10, 1, 2].sort();                       // [1, 10, 2]  ← not numeric!
[10, 1, 2].sort((a, b) => a - b);        // [1, 2, 10]  ← comparator, ascending
[10, 1, 2].sort((a, b) => b - a);        // [10, 2, 1]  ← descending

The default sort converts elements to strings and compares character by character — so 10 sorts before 2. Numeric sorting requires the comparator (a, b) => a - b. Also know: sort sorts in place (it mutates), while toSorted() is the non-mutating modern alternative.

Mutation matters map, filter, slice, concat → return new arrays (safe to chain). sort, reverse, splice, push/pop → mutate the original (surprising in shared state). "Which of these mutate?" is a standing interview question — and the source of real bugs when the array is shared.

Exceptions & traps — the complete list

  • sort() mutates AND compares as strings — [10, 1, 2].sort() → [1, 10, 2]. Numbers need (a, b) => a - b; use toSorted() for a non-mutating copy.
  • reduce without an initial value throws on empty arrays — always pass the accumulator seed.
  • Forgetting to return inside map gives an array of undefineds — silent, classic.
  • forEach can't be stopped — no break/continue; switch to for…of or use some/every which stop early.
  • splice vs slice: splice mutates; slice copies. One letter apart, opposite damage.
  • Chaining after a mutating method (sort → map) operates on the mutated original — surprising in shared state.
  • filter keeps truthy, not true — a callback returning "no" or 1 keeps the element.
  • indexOf misses NaN (strict comparison) — includes(NaN) works; different comparison rules.
  • map on sparse arrays / expecting side effects — map is for transformation; side effects belong in forEach/for…of.

4.Prove it

Your interview answer — rehearse out loud, recorded, no notes "map, filter and forEach all call my callback per element with the same arguments, but the return contracts differ: map returns a new array of the same length with transformed values, filter returns a shorter array of elements that passed the test, and forEach returns undefined — so I use map when producing data and forEach for side effects. reduce carries an accumulator through the array to a single value; I always pass an initial value because without one the accumulator starts as the first element and an empty array throws. And I know the sort trap: the default sort compares as strings, so numbers need a comparator like (a, b) => a - b — and sort mutates in place."

Contracts → reduce details → sort trap. Three beats, all first-hand knowledge.
