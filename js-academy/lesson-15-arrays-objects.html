Arrays & Objects

The two structures almost every program is built from — and the reference rule that breaks beginners.

In plain words An array is a numbered list — "give me item number 3." An object is a labeled box — "give me the thing called 'name'." And here is the big idea of this whole lesson: when you copy one of these into another variable, JavaScript does not copy the contents — it copies the arrow pointing at them. Two names, one list. Change it through either name, and both see the change.

1.Read the concept

Two containers, two ways to reach inside:

const todos = ["milk", "code"];         // a NUMBERED list — position 0, 1, 2…
const user  = { name: "Sam", age: 30 }; // a LABELED box — reach by key

Array: "give me item number 1" → todos[1]. Object: "give me the thing called name" → user.name. Simple. Now the twist that breaks everyone.

The twist — assignment copies the ARROW, not the box

const a = [1, 2];
const b = a;          // "copy" a into b — right?
b.push(3);
console.log(a.length);   // 3 ?!  — you changed b... why did a CHANGE?!

b = a did not copy the array — it copied the arrow pointing at it. Two name-tags, one array; mutate through either tag, and both names see it. A real copy needs spread:

const c = [...a];        // a REAL copy... of the TOP LEVEL only
c.push(77);              // ✅ independent — a and b untouched

But "shallow" means: if the array contains objects, the copy still shares them with the original — you copied the boxes on the top shelf, but the nested boxes are the same ones.

Now the definition makes sense Arrays and objects are handled by reference: assignment copies the arrow, never the contents. Independent copies need spread or slice() — and those are shallow. This one fact explains a huge share of "mystery bugs" in JavaScript.

Dot vs brackets — and the daily methods

const key = "city";
const o = {};
o[key] = "Berlin";     // ✅ brackets EVALUATE the variable → key "city"
o.key = "fail";        // dot does NOT evaluate — creates a literal key "key"!

const arr = [1, 2, 3, 4];
arr.slice(1, 3);       // [2, 3] — a COPY of that portion; arr untouched
arr.splice(1, 2);      // [2, 3] — REMOVED from arr itself; arr is now [1, 4]

Exceptions & traps — the complete list

  • Reference semantics: b = a then b.push() changes a too. Independent copy: [...arr], arr.slice(), {...obj}.
  • Spread is SHALLOW: nested objects and arrays are still shared with the original. True deep copy: structuredClone(obj).
  • const arrays can still change: const list = []; list.push(1) works — const locks the arrow (Variables lesson), not the contents.
  • slice vs splice: slice copies (safe), splice removes in place (destructive). One letter apart, opposite damage.
  • sort() mutates AND compares as strings: [10, 1, 2].sort() → [1, 10, 2]. Numbers need sort((a, b) => a - b). (Full treatment in Array Methods.)
  • indexOf can't find NaN (it compares strictly) — but includes(NaN) works. They use different comparison rules.
  • Missing nested reads throw: user.address.city crashes with "Cannot read properties of undefined" if address is missing — guard with optional chaining: user.address?.city.
  • delete obj.key removes the key entirely; obj.key = undefined leaves the key present with value undefined — "key" in obj stays true.
  • Object.keys lists own keys only; for…in also walks inherited ones (Prototypes lesson).
  • arr.length is writable: arr.length = 0 empties the array instantly — occasionally handy, often surprising.

4.Prove it

Your interview answer — rehearse out loud, recorded, no notes "Arrays are ordered lists accessed by index — push/pop at the end, unshift/shift at the start, and I keep slice (non-destructive copy) separate from splice (in-place removal). Objects are key-value collections: dot notation for known keys, brackets for dynamic ones, Object.keys and entries for enumeration. The critical rule is that both are reference types: assigning one variable to another doesn't copy the data, it copies the arrow — both names mutate the same object. Independent copies need spread or slice, and those are shallow, so nested objects still share. That reference rule is the source of most surprising bugs in JS."

Structures → methods → the reference rule. The last sentence is the one that lands.
